02 / Mathematical model

为什么 Path Graph 会让问题变简单？

对一般图，从 s 出发可以遇到分叉、环和绕路，节点集合的选择和访问顺序需要同时优化。路径图则是顶点排成一条链、任意两个顶点间只有一条简单路径的连通无向图。

令路径上的顶点依次为 v₁, v₂, …, vₙ，起点是 vₕ。连接 vᵢ 与 vᵢ₊₁ 的边耗时为 ℓᵢ ≥ 0，顶点奖励为 rᵢ ≥ 0，总时间预算为 T ≥ 0。

符号定义直观含义
L, R访问区间的左右端点，L ≤ h ≤ R最远向左 / 向右到哪里
A(L)ℓL + ··· + ℓh−1起点向左走到 vL 的距离
B(R)ℓh + ··· + ℓR−1起点向右走到 vR 的距离
P(L,R)Σi=L..R ri区间内只计一次的奖励总和
C(L,R)覆盖整个区间所需最少移动时间必须决定先左后右，还是先右后左
关键约束：你们研究的版本允许随时结束路线；经典文献中经常出现“指定终点”的 Orienteering 版本。英文报告开头必须讲清楚这里是 rooted, free-endpoint，否则后面的成本公式可能被质疑。
03 / Central idea

两个引理决定了整个算法

引理 1：你访问过的节点，一定构成一个连续区间

假设玩家从 vₕ 出发，曾经到过最左侧 vL 和最右侧 vR。因为图上没有捷径，去往两个端点的过程必然经过它们之间的所有节点，所以被访问的顶点集合恰好是 [L, R]。

为什么这很重要？

一般图要讨论“访问哪些点、顺序如何”；路径图只需选 两个整数 L、R。一旦决定了最左和最右位置，收集到的奖励就确定了。

引理 2：覆盖 [L,R] 的最少时间如何算？

记 A 为从起点到左端点的距离，B 为从起点到右端点的距离。想同时访问两端，你有且只有两种值得考虑的先后顺序：

先去左，再去右

s → L 花 A；L → R 花 A+B；最终停在 R。

A + (A + B) = 2A + B
先去右，再去左

s → R 花 B；R → L 花 A+B；最终停在 L。

B + (A + B) = A + 2B
C(L,R) = min(2A + B, A + 2B) = A + B + min(A,B)

证明不是只说这两条路“看上去最短”。要同时说明：任何路线必先到达某一个端点，然后才可能到达另一个端点；前后两段移动所需的距离分别给出对应下界，而上述两条路线恰好实现这两个下界。

记忆方法：左右各走一遍需要 A+B；由于起点在区间中间，还要为其中一侧的“折返”多付一次成本。选择 离起点更近的那一侧先去，就能使重复经过的距离最小。

于是，原问题被完全改写为

maximize   P(L,R) = Σi=L..R risubject to   1 ≤ L ≤ h ≤ R ≤ n   and   A(L) + B(R) + min(A(L), B(R)) ≤ T

这里“完全”很关键：任何真实 walk 对应一个区间，而任何满足预算的区间都能由上述具体走法实现。算法找到的不是仅仅一个数学上的上界，而是真正可走的最优路线。

04 / Derivation and algorithm

先做 O(n²)，再把它变成 O(n)

第一版：枚举左右端点，已经是精确解

有最多 h × (n−h+1) = O(n²) 个区间。利用前缀和，每个区间都可以在常数时间内算出成本与奖励。枚举所有满足 C(L,R) ≤ T 的区间，取最高奖励即可。

这是一个可靠的 baseline，可以用来检查更快的实现。但你的最终贡献可以更进一步，因为奖励与移动成本都是非负数。

两个单调性，让双指针成为可能

  1. 固定左端点 L，右端点越往右，成本不会减少。因为 B(R) 随 R 不减，所以 C(L,R) 不减；可行的右端点总是一段前缀。
  2. 固定 L，右端点越往右，奖励不会减少。因为所有 rᵢ ≥ 0，所以在预算允许的范围里，取最远可行的 R 就足够了。
  3. 把 L 从左往右移动，原本可行的 R 不会突然不可行。因为 A(L) 不增，成本只会保持或下降。于是最远可行 R 只需往右移动，从不后退。
x₁ = 0,   xi+1 = xi + ℓi,   q₀ = 0,   qi = qi−1 + riA(L) = xh − xL;   B(R) = xR − xh;   P(L,R) = qR − qL−1
PSEUDOCODE · ExactPathOrienteering
Input: path v[1..n], edge times ℓ[1..n−1],
       rewards r[1..n] ≥ 0, start h, budget T
Compute distance prefix x[1..n]
Compute reward prefix q[0..n]

R = h
best = −∞
for L = 1, 2, ..., h:           // L 向右移动
    A = x[h] − x[L]
    if A > T: continue         // 连左端点都到不了

    while R < n:
        Bnext = x[R+1] − x[h]
        if A + Bnext + min(A, Bnext) > T:
            break
        R = R + 1              // R 永不回退

    reward = q[R] − q[L−1]
    if reward > best:
        best = reward
        (L*, R*) = (L, R)

// 先去离起点近的端点，再走到另一个端点
return best, constructWalk(h, L*, R*)

严格复杂度

L 最多递增 n 次；R 在整个执行中最多递增 n 次（不能把 while 当成每轮重新跑 n 次），前缀和构建也是 O(n)。因此：

Time = O(n)   ·   Space = O(n)   ·   Approximation ratio = 1

如果使用邻接表输入，需要先在 O(|V|+|E|) 时间内确认并提取路径顺序；对连通路径图有 |E|=|V|−1，所以总计仍为 O(n)。

06 / Ready-to-use formal writing

可用于 Final Report 的英文正文

可改成 main.tex 的新一节。单独的完整 LaTeX 版本随文档另附。

Exact Orienteering on a Path Graph

We consider the special case in which the underlying graph is an undirected path v1—v2—⋯—vn. Let ℓi ≥ 0 denote the cost of edge {vi,vi+1}, let ri ≥ 0 denote the reward at vertex vi, and let the starting vertex be s = vh. A walk may terminate at any vertex, and each reward is collected at most once.

For any 1 ≤ L ≤ h ≤ R ≤ n, define the distances from the start to the two extremes and the reward of their interval:

AL = Σi=L..h−1 ℓi,   BR = Σi=h..R−1 ℓi,   P(L,R) = Σi=L..R ri.

Lemma 1 (Interval property)

The set of vertices visited by any walk starting at vh is a contiguous interval [L,R] containing h, and its total collected reward is P(L,R).

Proof. Let L and R be the minimum and maximum indices visited by the walk. On a path graph, there is a unique simple path between any pair of vertices. Reaching either extreme from vh necessarily passes through every intervening vertex; therefore all vertices in [L,R] are visited. By the definition of the extremes, no other vertex is visited. Since reward is counted only once per vertex, the collected reward equals P(L,R). ∎

Lemma 2 (Minimum interval-covering cost)

The minimum cost of any walk starting at vh that visits both extremes of [L,R], without a prescribed endpoint, is

C(L,R) = min{2AL+BR, AL+2BR} = AL+BR+min{AL,BR}.

Proof. Any such walk must visit both vL and vR. If vL is the first extreme reached, reaching it from the start costs at least AL, and subsequently reaching vR costs at least AL+BR. The total cost is therefore at least 2AL+BR, achieved by travelling from vh to vL and then to vR. The opposite order analogously has minimum cost AL+2BR. The cheaper of these two orders is optimal, including when one extreme coincides with the start. ∎

By Lemmas 1 and 2, the original optimisation problem is equivalent to maximising P(L,R) over all 1 ≤ L ≤ h ≤ R ≤ n such that C(L,R) ≤ T. Enumerating all intervals gives an O(n²)-time exact algorithm after prefix-sum preprocessing. We next improve it to linear time.

Two-pointer algorithm

Compute distance prefix sums x1=0 and xi+1=xi+ℓi, and reward prefix sums q0=0 and qi=qi−1+ri. For each left endpoint L from 1 to h, maintain the largest feasible right endpoint R, initially h. Skip L if xh−xL > T. Otherwise, advance R while C(L,R+1) ≤ T. Evaluate qR−qL−1, and remember the highest-reward interval.

Theorem (Optimality and running time)

For a fixed starting vertex and an arbitrary ending vertex, the Orienteering Problem on an undirected path graph with nonnegative travel costs and nonnegative one-time vertex rewards can be solved exactly in O(n) time and O(n) space.

Proof. By Lemmas 1 and 2, every feasible walk gives a feasible interval of the same reward, and every feasible interval can be covered by a walk of cost C(L,R) ≤ T. Therefore it suffices to optimise over intervals.

Fix a left endpoint L. Because the travel costs are nonnegative, C(L,R) is nondecreasing as R increases. Thus its feasible right endpoints form a prefix, and there is a largest feasible R if AL ≤ T. As vertex rewards are nonnegative, P(L,R) is also nondecreasing in R, so this largest feasible R attains the highest reward among all feasible intervals with left endpoint L. If AL > T, no right endpoint is feasible, justifying its omission.

As L increases, AL does not increase. Since C(L,R)=AL+BR+min(AL,BR) is nondecreasing in AL, every previously feasible right endpoint remains feasible. Therefore the largest feasible R never decreases, and the algorithm maintains it correctly by only moving R to the right. It examines a best interval for every possible L and hence returns the global optimum.

The prefix arrays take O(n) time and O(n) space. The left pointer moves at most n times, and the right pointer advances at most n times in total, with O(1) work per iteration. Thus the total running time is O(n). Finally, an optimal walk is reconstructed by first visiting the nearer extreme and then the farther extreme, as established in Lemma 2. ∎

Scope and limitations

This exact linear-time algorithm relies on the structure of the underlying graph being a path, not merely on the returned route having the shape of a path. Branches and cycles destroy the interval property. Nonnegative rewards are needed to justify choosing the furthest feasible right endpoint for each L. The travel-cost formula also assumes a fixed start but no required finish or return to the start; variants with terminal constraints need a modified analysis. Dynamic travel times, respawning rewards and interactions with opponents lie outside the static model considered here.

07 / Critical evaluation

Limitations 应该怎么写，才不是泛泛而谈？

课程要求的不仅是“算法快”，还要清楚界定其适用范围、哪些前提在 MOBA 场景里不现实，以及推广到一般图时到底是哪一步失效。

限制为什么会影响证明报告里怎么表述
必须是路径图一般图存在分支、环；访问集合不能唯一表示为单个区间 [L,R]核心结构限制；在完整 MOBA 地图上不能直接应用
非负奖励如果 rᵢ 为负，向右扩张区间可能降低总奖励；“最远 R 最好”不再成立双指针最优性证明对负奖励无效，必须重新设计算法
起点固定，终点自由成本 C=min(2A+B,A+2B) 假设走到最后一个端点就能停必须回基地或到指定目标时需调整成本与证明
静态权重与一次性奖励现实游戏的移动时间、怪物刷新、争夺资源均可能变化精确性只对抽象模型成立，不保证实际比赛最优
不考虑敌人、战斗与收集耗时原模型将此类影响省略，新增约束可能改变可行路线是模型边界，不是该算法内部的数学错误
最容易被导师指出的问题：“任何方案最终都是一条 path，所以为什么不能对一般图使用你的 path graph 算法？”回答：这里要求的是 输入图本身是一条路径；不是说从任何一般图中挑出一条路线后，这条路线看起来像 path 就能套用 O(n) 结论。

可写进报告的讨论层次

理论意义：虽然一般 Orienteering 是 NP-hard，但其特殊拓扑允许精确多项式甚至线性时间算法，说明组合复杂度很大程度来自图的分支与访问顺序选择。

应用意义：对于单条走廊、线性地图或已经被证明可约化为路径的子地图，算法可以为 Demo 提供即时最优答案；但对于普通 MOBA 多路线地图，应继续使用 Held–Karp 作为小规模 benchmark，或使用经过分析的启发式算法。

可进一步讨论：终点固定/必须返回的变体、树图上的方法、带重新刷新的时间相关奖励；这些是后续研究方向，不应误写成已被当前定理解决。

08 / Integration repairs

前面如果还没修完，至少补这三处

A. NP-hardness 归约：修正预算和奖励门槛

目前 main.tex 的问题是：构造写了 T=n+1, R=n，但“反向证明”转而假定 T=n, R=n+1，并声称奖励上界为 n。三者不一致，原参数也不足以强制一条 Hamiltonian path。

建议统一采用更简洁的版本：令原始无向图 H 有 n 个顶点，在新图里新增起点 s 并连到 H 的每个顶点，所有边权为 1，r(s)=0，每个原始顶点奖励为 1，设 T=n，K=n。
修订后的当且仅当证明

⇒ 若 H 存在 Hamiltonian path v₁→⋯→vₙ，则新图的 s→v₁→⋯→vₙ 经过 n 条边，耗时 n，获得 n 个原始节点的全部奖励，故满足条件。

⇐ 若新图存在成本 ≤n、奖励 ≥n 的 walk，它必须访问全部 n 个原始顶点。从 s 出发首次到访 n 个不同的顶点至少需 n 次边遍历；每条边权为 1 且预算为 n，因此恰好 n 次遍历，没有任何重复。去掉最初的 s 后，剩余顺序是原始图 H 的 Hamiltonian path。

构造仅新增 1 个顶点和 n 条边，耗时 O(|V|+|E|)，是多项式归约。该判定问题因此 NP-hard。

另一种一致的写法是令 r(s)=1、其余奖励仍为 1，并设 T=n、K=n+1；不要混用两版。

B. Held–Karp：复杂度记号与“exactly” 的歧义

现有 main.tex 写了 |V|=m, |E|=n，却又声称 Dijkstra 运行 n 次、DP 用 2ⁿn²，这会把边数和顶点数混淆。更合理的是用 N=|V|, M=|E|, k=|P|，P 为正奖励节点集合。

DP time = O(k² 2ᵏ);   Dijkstra preprocessing = O((k+1)(N+M) log N)使用二叉堆与邻接表的保守上界；总时间为两项之和。

DP 的 dp[S][v] 是“在最短路距离闭包上，按顺序访问指定奖励节点集合 S 并以 v 结束的最小费用”，但拼接真实最短路时 可能经过其他不在 S 的奖励节点。因此别写“真实 walk 恰好只访问 S”。由于奖励非负，额外经过的奖励节点只会提高实际收益；结合 Metric Closure Lemma 才能推出整体最优性。

其归纳证明要明确两边：任一合法 visiting order 去掉最后的 v 给出一个候选前驱，所以 DP ≤ 最优；任一 DP 转移都能构成合法 visiting order，所以 DP ≥ 最优。由此得等号。

C. Greedy 的 unbounded approximation ratio：补一个严格反例

如果 Tenuun 仍未完成，可针对两种明确的贪心规则——nearest next feasible reward 和 highest reward / additional travel cost——用同一族反例说明两者的性能可能任意差。

取 M ≥ 3，令 w(s,a)=1, r(a)=2；w(s,b)=M, r(b)=M，并设 T=M。最近优先显然先选 a；奖励/距离比也先选 a（2/1 = 2，而 M/M = 1）。此时已经耗费 1，想从 a 再到 b，需追加 1+M，总耗时 M+2 > M，故贪心只能拿 2 分。

Greedy = 2,   OPT = M,   OPT / Greedy = M/2 → ∞

因此，随着 M 增大，这两种没有回溯或预见的具体贪心规则均不具有常数近似保证。不要把此结论扩大成“所有可能的 greedy algorithm 都没有近似保证”，因为不同贪心设计可能有不同性质。

特别有趣的对比：这个贪心反例的输入本身仍是路径图！所以你们可以展示：同一特殊图上，局部贪心可能任意差，而利用区间结构的 O(n) 算法却能得到严格最优解。

你的部分应该按什么顺序真正完成？

若只交一段“path graph 上可以扫描”而没有条件、引理和复杂度证明，这部分会显得很弱。建议按下面的顺序整合：

  • 锁定与组员一致的模型：无向路径图、非负边权、非负节点奖励、一次领取、固定起点、终点自由。
  • 写出 Path Graph 专节：定义 v₁…vₙ、起点 vₕ、A、B、P、C，附一张路径示意图。
  • 证明 Interval Lemma：任何实际 walk 的访问集合恰好是一个包含起点的连续区间。
  • 证明 Cost Lemma：对左右端点两种访问顺序分别作下界证明，并构造达到下界的 walk。
  • 先说明 O(n²) exact baseline：降低读者理解难度，再用单调性推导双指针 O(n)。
  • 完成算法正确性定理：证明最远可行 R 为固定 L 的最优；证明 R 永不回退；覆盖全部 L；给出时间、空间复杂度。
  • 写 limitations：至少写 topology、nonnegative rewards、free endpoint、static model 四项，并具体指出失败在哪一步。
  • 验证并整合：用第 05 节的手算案例核对，整理成最终报告中的一节；必要时帮组员修正第 08 节的三个问题。
建议最终贡献的叙事线：一般图 NP-hard → Held–Karp 可精确但指数级 → 简单 greedy 无界坏例 → 限制为路径图后，利用拓扑结构实现 O(n) 精确算法。这是你这部分最清晰、最有说服力的价值。
