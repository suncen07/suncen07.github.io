STEP 01

先把题目翻译成“能选哪些任务”

共有 n 个按顺序排列的任务。对任务 i，我们知道：

V[i]：选择任务 i 得到的奖励。

W[i]：做完任务 i 后，接下来的 W[i] 个任务都不能做。

k：最多只能做 k 个任务；可以做更少，也可以一个都不做。

目标：选出一组合法任务 S，让总奖励 ∑i∈S V[i] 最大。

“最多”而不是“恰好”。 这意味着做 0、1、…、k 个任务都允许。即使有负奖励的任务，我们也不必强迫自己选它。
STEP 02

第一个直觉：看当前任务，只有两种选择

假设现在来到任务 i，还允许做 t 个任务。我们只需要决定：跳过 i，还是选择 i？

A · Skip 跳过

任务 i 不做，奖励 +0；接下来从 i+1 开始，剩余名额仍为 t。

B · Take 选择

立即获得 V[i]；任务 i+1 至 i+W[i] 强制跳过；下一次从 i+W[i]+1 开始，名额变成 t−1。

用时间线看一次冷却

例如 W[3]=1。如果选择第 3 个任务，第 4 个任务不能选，但第 5 个任务重新变得可选。

一个非常重要的方向问题：由于 W[i] 约束的是任务 i 后面的任务，因此从左往右作选择、把未来当作子问题的 suffix DP（后缀 DP） 最直接。不要误用“当前任务的 W[i] 限制前面的任务”的前缀递推。
STEP 03

状态为什么要有两个参数？

要准确描述一个小问题，必须知道两件事：从哪个位置继续，以及还剩多少次选择机会。

DP(i, t)只考虑任务 i, i+1, …, n，最多选择 t 个合法任务所能获得的最大奖励。

例如：

  • DP(3,2)：只从任务 3 开始考虑，最多还能做 2 个。
  • DP(5,1)：从任务 5 开始，最多还能做 1 个。
  • DP(1,k)：从第一个任务开始且总共最多做 k 个——这正是原问题。
关键理解：状态里不需要记“之前选了哪些任务”，因为一旦我们决定选择某项任务，就直接跳过它所禁止的区间。到达一个新的 i 时，过去的影响已经由这个跳转处理完毕。
STEP 04

正式推出状态转移：Skip 和 Take 取最大

对于 1 ≤ i ≤ n 且 1 ≤ t ≤ k：

DP(i,t) = max { DP(i+1,t),   V[i] + DP(i+W[i]+1,t−1) }越过 n 的后缀被视为空后缀（奖励为 0）。

这不是“猜出”的公式，而是将前面的两个互斥选择转写成数学表达式：

第一项 DP(i+1,t)：不做任务 i，所以从下一个任务开始，名额不减少。

第二项 V[i]+DP(i+W[i]+1,t−1)：做任务 i，先拿当前奖励，然后跳过冷却区，继续寻找剩余最多 t−1 项。

为什么取 max？ 每一个合法解都属于“选择 i”或者“不选择 i”之一。两种情况中只需保留奖励更高的。

为什么最后的位置不是 i+W[i]？

因为禁止的是后面 W[i] 个任务，具体是 i+1, i+2, …, i+W[i]。所以首个可能再选择的任务是 i+W[i]+1。

STEP 05

Base cases 和填表顺序

DP(n+1,t) = 0  (0 ≤ t ≤ k) 没有任何任务了，最大收益是 0。
DP(i,0) = 0  (1 ≤ i ≤ n+1) 剩余最多可以做 0 个任务，只能全部跳过。

即使 i+W[i]+1 > n+1，它代表的也只是“再没有任务可做”。实现时统一把后缀索引截断到 n+1：

next(i) = min(n+1,  i+W[i]+1)

为了计算 DP(i,t)，我们会查找 DP(i+1,t) 和 DP(next(i),t−1)。由于 W[i] ≥ 0，这两个状态的任务下标都严格大于 i。

所以：从 i=n 递减到 i=1，对于每个 i 遍历 t=1, …, k 即可。最终答案为 DP(1,k)。

从答案倒推，选了哪几个任务？

  1. 看 DP(1,2)=17：跳过任务 1，能够获得 17；选择任务 1 只能得到 7+DP(4,1)=15。所以跳过。
  2. 看 DP(2,2)=17：跳过任务 2，能够获得 17；选择任务 2 则是 4+DP(3,1)=13。继续跳过。
  3. 看 DP(3,2)=17：跳过只得 14；选择任务 3 后可得 9+DP(5,1)=17，因此选择 3，同时禁止任务 4。
  4. 看 DP(5,1)=8：选择任务 5 得到 8，任务 6 被禁止。
结果：选择任务集合 S = {3,5}，收益 9 + 8 = 17，共做了 2 个任务，恰好不超过 k=2，且两次选择不违反冷却约束。
STEP 07

写成可交卷的算法，以及复杂度

以下代码假设 V 和 W 是 Python 的 0-based 数组，但数学上的任务编号仍为 1,…,n。

def maximum_reward(V, W, k):
    n = len(V)
    k = min(k, n)  # 最多也只能选 n 个任务

    # dp[i][t] = 任务 i..n 中最多做 t 项的最大收益
    # 第 n+1 行，以及第 0 列，初始全为 0
    dp = [[0] * (k + 1) for _ in range(n + 2)]

    for i in range(n, 0, -1):
        j = min(n + 1, i + W[i - 1] + 1)
        for t in range(1, k + 1):
            skip = dp[i + 1][t]
            take = V[i - 1] + dp[j][t - 1]
            dp[i][t] = max(skip, take)

    return dp[1][k]

测试用例：V = [7,4,9,6,8,5]，W = [2,0,1,0,1,0]，k = 2，结果为 17。

时间复杂度：O(nk)

一共最多 n(k+1) 个状态。每个状态只计算 Skip、Take 两个常数时间的值，因此总时间为 O(nk)。

空间复杂度：O(nk)

二维 DP 表有 (n+2)(k+1) 个位置，使用 O(nk) 空间。不能随便只保存上一行，因为 Take 可能跳到许多行之后。

严格地讲，如果 k > n，实现中将其截断为 n，时间和空间可表述为 O(n·min(k,n))；统一写作 O(nk) 也是正确的多项式上界（假设 k≥1）。

STEP 08

正确性证明究竟要证明什么？

对于动态规划，不能只写“公式显然正确”。证明时最重要的是：为什么最优解一定落在 Skip 或 Take 的两个子问题中，而且这两种情况不会遗漏合法解。

① 先假设子问题已经算对

我们使用逆向归纳（backward induction）：从空后缀开始，假设任务下标比 i 大的所有相关子问题都正确。

② 对 DP(i,t) 的最优解分两类

取一个在任务 i,…,n 中最多选择 t 项的最优合法解 S。

Case 1：i∉S。剩下只可能来自 i+1,…,n，所以最优值为 Skip 分支的 DP(i+1,t)。

Case 2：i∈S。剩下不能包含 i+1,…,i+W[i]，最多还能选 t−1 项，所以最优值为 Take 分支的 V[i]+DP(next(i),t−1)。

③ 为什么子问题最优可以直接拼接？

选 Skip 的任何合法后缀解，加入“跳过 i”的决策仍合法；选 Take 的任何合法后缀解，加上任务 i 也合法，因为冷却区已被跳过。若子问题解不是最优的，就可以换成更优的后缀，从而改进总解，与最优性矛盾。

④ 收尾

所有合法解都恰好属于两个 Case 的其中一个，因此取两者最大即为最优。用归纳推出所有状态正确，特别是 DP(1,k)。

写考试证明时建议记住的结构：定义状态 → 说明两种情况及合法性 → 归纳说明子问题最优 → 递推式成立 → 输出原问题状态。文末英文证明严格按照这条线展开。
STEP 09

最容易丢分的四个问题

误区 1：用 DP(i−W[i]−1, t−1) 回头找前一个任务
错误。 当前任务 i 的 W[i] 只决定它后面不可选择的任务，不能反推前面哪些任务和它兼容。反例：n=2, k=2, V=[10,9], W=[1,0]。任务 1 做了就不能做 2，正确最优值是 10；错误的前缀式公式可能算出 19。
误区 2：选择任务 i 后，从 i+W[i] 继续
少跳过了一个位置。被禁止的是 i+1 到 i+W[i]，所以必须从 i+W[i]+1 继续。如果 W[i]=0，才直接去 i+1。
误区 3：把“最多 k 项”写成“恰好 k 项”
这会改变问题。用最多 t 项的定义，DP(i,0)=0 自然正确；即使奖励有负数，也允许直接跳过。若定义恰好选 t 项，通常需要用不可行值 −∞ 来处理某些状态，复杂且没有必要。
误区 4：复杂度写成 O(n²k)
本题的下一位置 next(i)=i+W[i]+1 可以在 O(1) 时间算出，不需要枚举后续的每一个任务。因此每个 (i,t) 状态只做常数次工作，总时间是 O(nk)。
FORMAL ANSWER

Formal English Solution & Proof

以下部分参照 sample answer 的组织方式：Solution → Recurrence → Base cases → Final solution and order of evaluation → Time complexity → Correctness。可作为作业/考试书面证明的参考版本。

Solution.

For each 1 ≤ i ≤ n+1 and 0 ≤ t ≤ k, let DP(i,t) denote the maximum total reward obtainable by performing at most t tasks among tasks i,i+1,…,n, subject to the cooldown constraints. If i=n+1, the remaining set of tasks is empty.

  • Recurrence. For each 1 ≤ i ≤ n and 1 ≤ t ≤ k, consider whether task i is performed. If task i is skipped, the optimal reward is DP(i+1,t). If task i is performed, we gain V[i], cannot perform any of the next W[i] tasks, and may perform at most t−1 additional tasks starting from task i+W[i]+1. Define next(i)=min{n+1,i+W[i]+1}. Thus, the subproblem satisfies the recurrence
    DP(i,t) = max{DP(i+1,t),  V[i] + DP(next(i),t−1)}.
  • Base cases. Since no reward can be earned without selecting any tasks, or when no tasks remain, set
    DP(i,0)=0  for  1≤i≤n+1,
    DP(n+1,t)=0  for  0≤t≤k.
  • Final solution, order of evaluation. The required maximum reward is DP(1,k). Fill the two-dimensional table in decreasing order of i, from n down to 1, evaluating all t=1,…,k for each i. Both i+1 and next(i) are strictly greater than i, so all states needed by the recurrence have already been computed.
  • Time complexity. There are O(nk) subproblems. Each subproblem is evaluated in O(1) time using two table lookups and a constant number of arithmetic and comparison operations. Hence the total running time is O(nk), and the table occupies O(nk) space. Therefore, the algorithm is polynomial in n and k.
  • Correctness. We prove by backward induction on i that DP(i,t) gives the maximum reward of a feasible selection of at most t tasks from {i,…,n}, for every 0 ≤ t ≤ k.

    Base cases. If i=n+1, no tasks remain, so the optimum is 0. If t=0, no task may be selected, so the optimum is also 0. Thus the base cases are correct.

    Inductive step. Fix 1 ≤ i ≤ n and t ≥ 1. Assume that the values of all subproblems whose first task index is greater than i have been computed correctly. Let S be an optimal feasible selection from {i,…,n} using at most t tasks. There are two cases.

    If i∉S, then S is a feasible selection from {i+1,…,n} using at most t tasks. By the inductive hypothesis, the maximum reward obtainable in this case is DP(i+1,t).

    If i∈S, then tasks i+1,…,i+W[i] cannot be selected. Consequently, S\{i} is a feasible selection from {next(i),…,n} using at most t−1 tasks. By the inductive hypothesis, the maximum reward obtainable in this case is V[i]+DP(next(i),t−1). Conversely, combining task i with any feasible solution to this suffix subproblem is valid, since all tasks prohibited by performing i have been excluded.

    Every feasible selection either contains task i or does not contain it. These two cases are exhaustive, and their optimal values are exactly the two terms in the recurrence. Therefore,

    DP(i,t) = max{DP(i+1,t),  V[i]+DP(next(i),t−1)}

    is optimal. The inductive step follows. By induction, all computed entries are correct, and in particular DP(1,k) is the maximum total reward achievable under the given constraints.

∎
